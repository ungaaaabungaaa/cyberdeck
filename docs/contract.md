# CyberDeck contract, version 1

The reviewed REST contract is [api/openapi.json](api/openapi.json). It describes two read-only GET endpoints under `/api/v1`, nullable live metrics, explicit fixture replay provenance, numeric calculator limits, response/error shapes, and loopback host restrictions. No authentication, remote binding, write endpoint, command execution, network scanning, or device control is exposed. HEAD has the same headers without a body. Serve only fixed public assets, at most 1 MiB each; never serve repository directories or configuration files. Reject unknown hosts, methods, routes, query keys, duplicate query keys, oversized request targets, and nonfinite values. Return generic bounded errors without local paths or stack traces.

Live status reads fixed Linux `/proc` and `/sys` metric paths and real disk totals only. Each source file is bounded to 64 KiB or less. Missing or malformed fields remain null and are listed in `missing`. Do not substitute fixture values in live mode. Memory available must not exceed total; disk free must not exceed total. Temperature is Celsius; load is a one-minute load average, not CPU utilisation. Battery percentage is supplied only by an OS power-supply sensor; it is not inferred from the power calculator. Replay samples are explicitly synthetic, deterministic fixtures with trace-relative elapsed time and a null collection timestamp. Browser history contains received samples only, at most 60; missing values create gaps.

The energy model accepts exactly five optional finite numeric fields with the defaults/ranges in OpenAPI. Unknown keys and booleans fail. Calculated runtime assumes constant load, declared battery Wh and efficiency. Reserve reduces output energy before calculating usable runtime. Nominal source-rating comparison is separate. No SOC, runtime benchmark, electrical approval, peak-load, thermal, or portable battery compatibility claim follows.

The enclosure generator uses millimetres and explicit dimensional bounds. Default outer size is 240 × 160 × 70 mm with 3 mm wall/face, 156.5 × 89 mm viewing window, and four 3.4 mm corner clearances at 8 mm inset. The 7-inch Touch Display 2 outline is 189.5 × 120 × 15 mm in landscape, with 155.5 × 88 mm viewing area. Keep at least 2 mm minimum walls, 6 mm display margin, and 54 mm internal depth for an unverified component/cable allowance (15 mm display + 8 mm mount allowance + 18 mm board allowance + 10 mm cable allowance + 3 mm retainer). Source comprises a removable front panel, shell, and retention frame in OpenSCAD plus an SVG panel drawing and a metadata report. The Pi attaches to the manufacturer's display mounts, not an invented enclosure hole pattern. Cable access and vents are provisional; measured fit, retention, material, cable bends, heat, and printing remain pending. No enclosure battery-cell or mains wiring design is supplied.

CLI commands: `serve [--live] [--port PORT]`, `status [--live]`, `budget [--config JSON]`, `enclosure --out NEW_DIR [--config JSON]`, and `prepare --out NEW_DIR --user USERNAME`. Replay is the default. Config files must be regular bounded UTF-8 JSON objects, at most 16 KiB and depth 8. Destinations must not exist; their parent must exist. Refuse symlink inputs and overwrites. Setup generation writes a systemd user-service template, a labwc autostart fragment, and manual deployment steps; it never installs, enables, flashes, reboots, changes host files, or invokes a shell. Username must match `[a-z_][a-z0-9_-]{0,31}` and is used only in a fixed target path. Exit codes: 0 success, 2 invalid input, 1 I/O/runtime failure.

Only new source receives the MIT license. The original unlicensed Android application remains on the remote archive branch; none of its code/assets are reused. Approved cover 13 is concept art. Generated diagrams/replay traces are program output, not hardware evidence. Physical assembly, actual Pi boot and metrics, systemd/kiosk operation, CAD rendering, printed fit, electrical and thermal tests remain pending until directly measured.
